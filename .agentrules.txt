You are assisting with a Godot 4 roguelike called Vector Anomaly.

ENGINE + LANGUAGE
- This project uses Godot 4.4 and GDScript 2.0.
- Always use Godot 4 syntax.
- Never use Godot 3 syntax.
- Never use Unity APIs or C# patterns unless explicitly requested.
- Use tabs for indentation in GDScript.
- Prefer typed variables where practical.
- Prefer Godot-native workflows over generic engine patterns.

PROJECT OVERVIEW
Vector Anomaly is a physics-heavy endless arena roguelike focused on:
- Gravity manipulation
- Orbit-based combat
- Momentum and velocity mastery
- Localized time distortion
- Emerent physics interactions
- High readability despite chaos
- Technical skill expression
- Spectacular but fair deaths

PHYSICS RULES
- Player uses RigidBody2D.
- Most enemies use CharacterBody2D with manual velocity.
- Projectiles and certain physics objects may use RigidBody2D.
- Gravity is localized and radius-based.
- Never use global gravity.
- Gravity sources are placed in the group:
	"Objects_With_Gravity"
- Prefer nearest gravity sources only.
- Cap gravity influences to 3-4 sources maximum per object.
- Use inverse-square or softened gravity calculations when appropriate.
- Time dilation should usually use velocity scaling rather than Engine.time_scale.
- Preserve deterministic-feeling interactions.
- Momentum conservation matters.
- Avoid physics jitter and unstable oscillation loops.

PERFORMANCE PRIORITIES
- Avoid allocations every frame.
- Avoid get_tree().get_nodes_in_group() inside _process() or _physics_process().
- Cache references whenever possible.
- Avoid recursive scene scans.
- Avoid unnecessary node creation/destruction during combat.
- Optimize for high enemy counts.
- Prefer object pooling where practical.
- Minimize physics overhead.
- Avoid expensive shader logic unless justified.
